# Iron Strength · Android e iPhone

Cliente móvil: **acceso con la cuenta existente, Inicio, Entrenar, Historial, Progreso y Cuenta**. Incluye vista previa, registro de series, objetivos por serie, superseries, descanso, alternativas, cierre con esfuerzo/nota y recuperación local. La consulta no inicia un entrenamiento: hay una acción explícita para empezar. El coach continúa planificando en la web. Incluye descarga explícita de semanas, cola de cierres y sincronización mientras la app está abierta. La distribución en tiendas y la aceptación física del arranque sin Metro siguen pendientes.

## Desarrollo

Desde la raíz del repositorio, instalar `npm ci`; después, en `mobile`, ejecutar `npm ci`. Son instalaciones independientes: no compartir node_modules de React entre Next y Expo. La app usa SDK 58 para coincidir con el Expo Go instalado en el iPhone del propietario; `npx expo-doctor` comprueba compatibilidad de paquetes. La primera entrega usó SDK 57, que ese Expo Go rechaza explícitamente. No editar carpetas ios/android generadas.

- `npm start`: Expo Go en la red local.
- `npm start -- --tunnel --go`: enlace temporal para otra red. El computador debe permanecer encendido y Metro activo. El túnel sirve una versión de desarrollo, no una app publicada en tiendas.
- `npm run check`: lint, tipos y pruebas de sesión.
- `npm run test:ui`: pantallas de Expo web con API sintética interceptada, Chromium y WebKit. Requiere los navegadores de Playwright instalados desde la raíz. No consulta ni siembra producción.
- `npm run bundle`: exporta JavaScript/Hermes y recursos de Android e iOS. **No genera APK/IPA ni firma un instalador.**

La prueba del propietario se inicia sin CI ni EXPO_OFFLINE: esos modos omiten anunciar el servidor en Expo Go. Al cambiar de SDK, reiniciar con `npm start -- --tunnel --go --clear` y comprobar que el manifiesto declara 58. El enlace HTTPS `/_expo/loading?platform=ios` ofrece un botón Expo Go para abrir desde el mismo teléfono sin escanear un QR. La presencia del proyecto en Projects no acredita que haya un servidor conectado o que la versión sea compatible.

El origen de producción por defecto es https://iron-strength-seven.vercel.app. `.env.example` contiene solo configuración pública. Para desarrollo local se requieren ambas variables EXPO_PUBLIC_API_URL y EXPO_PUBLIC_ALLOW_LOCAL_API=1; el permiso HTTP solo funciona en desarrollo. Un teléfono no puede alcanzar el localhost del computador: usar la dirección de su red cuando corresponda. Nunca incluir claves Supabase administrativas en variables EXPO_PUBLIC.

## Sesión y privacidad

El servidor ofrece /api/mobile/v1, verifica el usuario y aplica RLS. No usar Server Actions ni cookies del navegador como API móvil. SecureStore conserva un sobre v2 con refresh token y perfil verificado (ID, nombre, correo y rol); el access token vive solo en memoria. El sobre v1 se migra tras una renovación válida y escritura/relectura confirmadas. Un formato desconocido o error de almacenamiento se conserva y bloquea el acceso local. La vista web de desarrollo usa memoria y vuelve al acceso al recargar. El borrado local y la renovación se serializan; las respuestas de una sesión anterior no reabren la cuenta. Una desconexión no elimina la credencial guardada.

El registro iniciado y su instantánea se conservan por cuenta en SQLite del dispositivo. El cierre congela el payload antes de enviarlo: los reintentos usan el mismo ID y contenido. Una respuesta perdida o una sesión expirada no eliminan el pendiente. Descargar semana guarda un paquete completo por cuenta. Tras una primera entrada/descarga online, la app instalada puede recuperar su identidad local verificada ante una caída transitoria del servicio, consultar e iniciar rutinas de la semana vigente y cerrar un registro pendiente sin enviarlo. Un 401 exige volver a entrar; nunca se usa otra cuenta de SQLite como identidad. Una copia vencida se consulta, pero solo un borrador ya iniciado puede continuar. La cola is:native-sync:v1:<cuenta> recibe cierres completos mediante comparación atómica y relectura antes de retirar el original. Conserva hasta 50 pendientes y 20 confirmaciones recientes; alcanzar el límite no elimina registros. Permite empezar otro entrenamiento elegible. Conectar renueva la misma cuenta; abrir, volver al primer plano o recuperar red activa el envío, con esperas de 5/15/30/60 segundos ante fallos transitorios y acción manual. No depende de ejecutar con la app cerrada. Rechazos de datos/permiso detienen su reintento automático y conservan cuerpo/causa para revisión. Solo un recibo coincidente y persistido confirma el resultado; las vistas abiertas se actualizan. Una transferencia interrumpida se consolida por ID/contenido al reabrir. La independencia física de Metro se valida con binarios preview en T201; Expo web mantiene sus credenciales solo en memoria y no acredita apertura física en frío. Antes de salir hay que enviar/retomar o descartar explícitamente los entrenamientos pendientes, con confirmación de descarte. La salida y el borrado pausan los nuevos envíos y esperan escrituras en curso; una cola de formato desconocido se conserva al salir y solo se borra en la eliminación explícita de la cuenta. La salida retira el acceso local y registros resueltos/demos de esa cuenta, conserva su descarga separada por identidad y procura revocar solo su sesión móvil. Sin conexión no se afirma revocación remota.

## Probar en teléfono

Usar Expo Go compatible con SDK 58. Para iPhone, iniciar sesión en Expo Go y en la CLI con la misma cuenta Expo: desde la raíz ejecutar `npm run mobile:login`, completar el acceso en el navegador de este computador y reiniciar Metro. No pegar contraseñas ni códigos en el chat. Este acceso de desarrollo es distinto de la cuenta de Iron Strength dentro de la app. [Requisito oficial de Expo Go](https://expo.dev/changelog/expo-go-57-login). Después abrir el enlace temporal emitido por Metro. Android permite escanear el QR desde Expo Go; en iPhone se puede abrir desde Cámara o el enlace de Expo. El acceso y las rutinas dependen de la cuenta real existente: esta entrega no crea usuarios o programas ficticios en producción. Sin programa, debe aparecer el estado correspondiente.

Comprobar con cuenta propia: entrar → Inicio → Ver rutina → empezar → registrar kg/repeticiones → completar serie → finalizar → guardar → resultado → historial/progreso → Cuenta → salir. Sin programa, Entrenar ofrece tres sesiones demo: ver, probar, recuperar y terminar. Sus resultados quedan marcados DEMO en el dispositivo, no se asigna un programa ficticio ni se envían entrenamientos de ejemplo al coach. Cerrar y reabrir debe recuperar la sesión; desconectar al recuperar permite reintentar; cerrar sesión no debe cerrar la web. Registrar teclado, lector de pantalla, tamaño de texto, tema y retorno desde segundo plano por separado en specs/008-native-app/validation.md. Expo web no sustituye estos controles físicos.

## Antes de distribuir en tiendas

Faltan aceptación física del registro/descarga/cola sin Metro, identificadores de aplicación del propietario, cuentas Apple/Google, firma y distribución interna. EAS está vinculado al proyecto existente @domarchis/iron-strength-mobile (1374e5c4-2620-4034-b8b7-e32e479ff9c8); la CLI está autorizada como domarchi. Android preview ya tiene firma EAS y builds internos; code 2 conserva un cierre conocido y no se distribuye. Code 3 corrige comentarios/teclado/área segura y code 4 está en preparación con el selector de tema adaptado al texto ampliado. Ver docs/native-distribution.md desde la raíz para el artefacto vigente. No hay IPA o envío a tiendas ni se contrató un servicio de pago. La auditoría actual conserva avisos transitivos del SDK: revisar la actualización compatible y la exposición antes de una build distribuible; no ejecutar audit fix --force ni degradar Expo a SDK 44 para silenciarlos. Detalle y evidencia en specs/008-native-app/validation.md.
